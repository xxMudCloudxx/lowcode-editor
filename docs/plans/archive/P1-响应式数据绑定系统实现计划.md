# PLAN: 响应式数据绑定系统（完整运行时）

## Context

当前项目的 Renderer 只能处理静态 props——组件属性面板输入什么值，渲染时就原样传给组件。这意味着：

- 组件无法根据页面状态动态变化（如"购物车数量"显示在标题里）
- 无法实现"千人千面"等数据驱动场景
- 无法做条件显隐、动态文案等基础低代码能力
- 面试中被追问"发布后页面如何响应数据变化"时无法给出实现证据

这是低代码平台从"静态搭建工具"升级为"动态应用平台"的核心能力缺口。

### 现有基础

- `IRJSExpression` 类型已在 `packages/schema/src/ir.ts` 中定义（仅出码使用）
- `sandboxExecutor.ts` 提供了 `new Function` + iframe 沙盒执行模式
- Renderer 的 per-node subscription 模式天然支持局部重渲染
- 属性面板的 `FormElementRenderer` 已有动态渲染不同控件的能力

## Goal

完成后用户能观察到：

1. 属性面板每个字段旁有"绑定"按钮，点击可切换为表达式输入模式
2. 表达式中可引用 `$page.xxx`、`$global.xxx`、`$data.xxx`、`$system.xxx`、`$props.xxx`
3. 预览模式下，表达式实时求值并驱动组件渲染
4. 修改页面变量/全局变量后，依赖该变量的组件自动更新
5. 可配置数据源（API URL），运行时自动请求并注入 `$data`
6. 有变量管理面板可定义和编辑页面/全局变量

## Non-Goals

- 不做 AST 级精确依赖提取（本阶段用正则）
- 不做出码适配（表达式在生成代码中的输出留给全量阶段）
- 不做条件渲染（v-if）和循环渲染（v-for）
- 不做表达式的语法高亮和自动补全（属性面板用普通 textarea）
- 不做服务端存储（变量和数据源配置存在 localStorage 的 store 中）

## Scope

| 包 | 变更类型 |
|---|---|
| `packages/expression`（新建） | 核心引擎：求值、依赖提取、上下文类型 |
| `packages/schema` | 新增 `JSExpression` 类型到 Component props 契约 |
| `packages/renderer` | RenderNode 集成表达式求值 |
| `packages/editor` | 上下文 store、绑定 UI、变量面板、数据源面板 |

## Risks

| 风险 | 缓解措施 |
|---|---|
| Schema 变更影响所有包 | 表达式类型复用已有 IRJSExpression 结构，最小化契约变更 |
| Renderer 耦合 editor 状态 | 表达式上下文通过 props 注入，不在 renderer 内 import editor store |
| new Function 安全风险 | 限制可访问变量白名单，禁止 DOM/网络访问 |
| 性能：大量表达式频繁求值 | 依赖追踪确保只重算变化路径相关的表达式；求值结果缓存 |
| 属性面板 UI 复杂度增加 | 绑定模式作为独立组件封装，不侵入现有 FormElementRenderer |

#### 具体工作

**1. 初始化包结构**

```
packages/expression/

├── tsconfig.json
├── src/
│   ├── index.ts          # 统一导出
│   ├── types.ts          # ExpressionContext, ExpressionBinding, EvalResult
│   ├── evaluate.ts       # 核心求值函数

│   └── context.ts        # 上下文构建辅助函数
└── __tests__/
    ├── evaluate.test.ts
    └── extract-deps.test.ts
```

**2. 核心类型定义 (`types.ts`)**

```ts
// 表达式绑定值（存储在 Component.props 中）
export interface ExpressionBinding {
  type: 'JSExpression'
  value: string  // 如 "$page.userName + ' 的购物车'"
}

// 五层表达式上下文
export interface ExpressionContext {
  $global: Record<string, unknown>   // 全局变量（跨页面共享）
  $page: Record<string, unknown>     // 页面级变量
  $data: Record<string, unknown>     // 数据源返回值
  $props: Record<string, unknown>    // 当前组件的 props
  $system: Record<string, unknown>   // 系统变量（时间、路由参数等）
}

// 求值结果
export type EvalResult =
  | { ok: true; value: unknown }
  | { ok: false; error: string }
```

**3. 求值函数 (`evaluate.ts`)**

```ts
export function evaluate(expr: string, context: ExpressionContext): EvalResult {
  try {
    const fn = new Function(
      '$global', '$page', '$data', '$props', '$system',
      `"use strict"; return (${expr});`
    )
    const value = fn(
      context.$global, context.$page, context.$data,
      context.$props, context.$system
    )
    return { ok: true, value }
  } catch (e) {
    return { ok: false, error: (e as Error).message }
  }
}
```

**4. 依赖提取 (`extract-deps.ts`)**

```ts
// 正则匹配 $xxx.path.to.value 模式
const DEP_REGEX = /\$(global|page|data|props|system)(?:\.[a-zA-Z_$][\w$]*)+/g

export function extractDeps(expr: string): string[] {
  const matches = expr.match(DEP_REGEX)
  return matches ? [...new Set(matches)] : []
}
```

**5. 辅助函数 (`context.ts`)**

```ts
export function createEmptyContext(): ExpressionContext {
  return { $global: {}, $page: {}, $data: {}, $props: {}, $system: {} }
}

export function isExpression(value: unknown): value is ExpressionBinding {
  return (
    typeof value === 'object' && value !== null &&
    (value as any).type === 'JSExpression' &&
    typeof (value as any).value === 'string'
  )
}
```

#### 验证

```bash
pnpm --filter @lowcode/expression test
pnpm --filter @lowcode/expression exec tsc --noEmit
```

测试用例覆盖：
- 基本表达式求值：`"1 + 2"` → 3
- 上下文变量访问：`"$page.count * 2"` → 正确值
- 错误处理：语法错误返回 `{ ok: false }`
- 依赖提取：`"$page.name + $data.list.length"` → `["$page.name", "$data.list.length"]`
- `isExpression` 类型守卫正确识别

### M2: packages/schema — 表达式类型契约

#### 目标结果

- `Component.props` 的值类型正式支持 `ExpressionBinding`
- 从 `@lowcode/schema` 导出表达式相关类型，供所有包使用
- 不破坏现有静态 props 的兼容性

#### 具体工作

**1. 在 `packages/schema/src/expression.ts` 新增类型**

```ts
/**
 * 表达式绑定值 — 存储在 Component.props 中
 * 当 prop 值为此类型时，Renderer 需要调用表达式引擎求值
 */
export interface ExpressionBinding {
  type: 'JSExpression'
  value: string
}

/**
 * 数据源配置 — 存储在页面/全局配置中
 */
export interface DataSourceConfig {
  id: string
  name: string
  url: string
  method: 'GET' | 'POST'
  params?: Record<string, unknown>
  autoFetch?: boolean  // 页面加载时自动请求
}

/**
 * 变量定义
 */
export interface VariableDefinition {
  name: string
  defaultValue: unknown
  description?: string
}

/**
 * 页面级绑定配置（存储在 Page 组件的 props 或独立字段中）
 */
export interface PageBindingConfig {
  variables: VariableDefinition[]
  dataSources: DataSourceConfig[]
}
```

**2. 更新 `packages/schema/src/index.ts` 导出**

新增导出 `expression.ts` 中的所有类型。

**3. 兼容性设计**

`Component.props` 保持 `any` 类型不变（已有代码不受影响）。表达式值通过运行时类型守卫 `isExpression()` 识别，而非编译时强制。这样：
- 旧的静态 props 完全兼容
- 新的表达式 props 通过 `{ type: "JSExpression", value: "..." }` 存储
- Renderer 在渲染时判断：是表达式就求值，否则直传

### M3: packages/renderer — 集成表达式求值

#### 目标结果

- RenderNode 在合并 props 时，自动识别表达式类型的值并调用引擎求值
- 表达式上下文通过 SchemaRendererProps 注入（不破坏 renderer 的纯渲染契约）
- 上下文变化时，依赖该上下文的组件自动重渲染

#### 具体工作

**1. 扩展 `SchemaRendererProps`（`packages/renderer/src/types.ts`）**

```ts
import type { ExpressionContext } from '@lowcode/expression'

export interface SchemaRendererProps {
  // ... 现有字段保持不变 ...

  /**
   * 表达式上下文（仅 designMode="live" 时生效）
   * 由 editor 侧构建并注入，renderer 不管理上下文状态
   */
  expressionContext?: ExpressionContext
}
```

**2. 扩展 RendererContext（`SchemaRenderer.tsx`）**

在 `RendererContextValue` 中新增 `expressionContext` 字段，通过 Context 传递给所有 RenderNode。

**3. 修改 RenderNode 的 props 合并逻辑**

在 `SchemaRenderer.tsx` 的 RenderNode 中，合并 props 时加入表达式求值：

```ts
import { evaluate, isExpression } from '@lowcode/expression'

// 在 mergedProps 构建后，遍历并求值表达式
const resolvedProps: Record<string, unknown> = {}
for (const [key, val] of Object.entries(mergedProps)) {
  if (isExpression(val) && expressionContext) {
    const result = evaluate(val.value, {
      ...expressionContext,
      $props: mergedProps  // $props 指向当前组件的静态 props
    })
    resolvedProps[key] = result.ok ? result.value : undefined
  } else {
    resolvedProps[key] = val
  }
}
```

**4. 上下文变化触发重渲染**

`expressionContext` 作为 SchemaRenderer 的 prop 传入。当 editor 侧的上下文 store 变化时，会传入新的 `expressionContext` 对象，触发 Context 更新。

由于 Renderer 已有 per-node subscription 模式，这里需要确保 expressionContext 变化时能通知到使用了表达式的节点。方案：将 expressionContext 放入 RendererContext（而非 componentsRef），这样 context 变化会触发所有使用了表达式的节点重渲染。

**5. 依赖方向**

```
packages/expression (新)
    ↑
packages/renderer (新增依赖)
```

在 `packages/renderer/package.json` 中添加 `@lowcode/expression` 依赖。

#### 验证


#### 目标结果

- 新增 `useExpressionStore`，管理页面变量、全局变量、数据源状态
- 构建完整的 `ExpressionContext` 对象并传递给 Renderer

#### 具体工作

**1. 新建 `packages/editor/src/editor/stores/expressionStore.ts`**

```ts
import { create } from 'zustand'
import { immer } from 'zustand/middleware/immer'
import { persist } from 'zustand/middleware'
import type { ExpressionContext, DataSourceConfig, VariableDefinition } from '@lowcode/schema'

interface ExpressionState {
  // 变量定义
  globalVariables: VariableDefinition[]
  pageVariables: VariableDefinition[]

  // 运行时值（预览模式下的实际值）
  globalValues: Record<string, unknown>
  pageValues: Record<string, unknown>
  dataValues: Record<string, unknown>   // 数据源返回值
  systemValues: Record<string, unknown> // 系统变量

  // 数据源配置
  dataSources: DataSourceConfig[]

  // Actions
  setGlobalVariable: (name: string, value: unknown) => void
  setPageVariable: (name: string, value: unknown) => void
  addVariable: (scope: 'global' | 'page', def: VariableDefinition) => void
  removeVariable: (scope: 'global' | 'page', name: string) => void
  addDataSource: (config: DataSourceConfig) => void
  removeDataSource: (id: string) => void
  updateDataSource: (id: string, config: Partial<DataSourceConfig>) => void
  fetchDataSource: (id: string) => Promise<void>
  fetchAllAutoDataSources: () => Promise<void>

  // 构建完整上下文
  buildContext: (componentProps?: Record<string, unknown>) => ExpressionContext
}
```

**2. `$system` 上下文内容**

```ts
// 系统变量（只读，自动填充）
const buildSystemValues = (): Record<string, unknown> => ({
  timestamp: Date.now(),
  date: new Date().toISOString().split('T')[0],
  url: window.location.href,
  pathname: window.location.pathname,
  search: Object.fromEntries(new URLSearchParams(window.location.search)),
})
```

**3. 数据源请求逻辑**

```ts
fetchDataSource: async (id) => {
  const ds = get().dataSources.find(d => d.id === id)
  if (!ds) return
  try {
    const resp = await fetch(ds.url, {
      method: ds.method,
      headers: { 'Content-Type': 'application/json' },
      body: ds.method === 'POST' ? JSON.stringify(ds.params) : undefined,
    })
    const data = await resp.json()
    set(state => { state.dataValues[ds.name] = data })
  } catch (e) {
    set(state => { state.dataValues[ds.name] = { __error: (e as Error).message } })
  }
}
```

**4. 集成到 SimulatorRenderer（预览模式）**

在 editor 的预览/live 模式入口中，从 `useExpressionStore` 获取 `buildContext()` 结果，作为 `expressionContext` prop 传给 SchemaRenderer。

关键文件：`packages/editor/src/renderer/RendererApp.tsx`（iframe 内的渲染入口）

**5. 持久化策略**

- `globalVariables` 和 `pageVariables`（定义）：persist 到 localStorage
- `dataSources`（配置）：persist 到 localStorage
- `globalValues`、`pageValues`（运行时值）：persist（用户设置的默认值需要保留）
- `dataValues`（接口返回）：不 persist（每次预览重新请求）
- `systemValues`：不 persist（实时计算）

## Decision Log

| 决策 | 原因 |
|---|---|
| 新建 `packages/expression` 而非放入 renderer | 未来 runtime 容器也需要表达式引擎，独立包便于复用 |
| 用 `new Function` 而非 iframe 沙盒 | 性能考虑：表达式求值频率高，iframe 开销太大；安全通过白名单变量控制 |
| 正则提取依赖而非 AST | 本阶段够用，接口设计好后续可无缝替换为 AST 实现 |
| expressionContext 通过 props 注入 renderer | 保持 renderer 纯渲染契约，不引入 editor store 依赖 |
| Component.props 保持 `any` 类型 | 最小化 schema 变更，通过运行时类型守卫识别表达式 |
| 变量定义 persist，数据源返回值不 persist | 定义是用户配置需要保留；接口数据每次预览应重新请求 |

## Rollback

- `packages/expression` 是新包，删除即可回退
- Schema 变更仅新增类型导出，不修改现有类型，删除导出即可

- Editor 的 store 和 UI 组件都是新增文件，删除即可
- 整体回退风险低：所有变更都是增量新增，不修改现有行为
