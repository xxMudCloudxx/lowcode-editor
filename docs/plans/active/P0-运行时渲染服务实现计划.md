# P0 运行时渲染服务实现计划

## Context

面试官指出项目短板：「发布之后后面的流程，然后他是怎么去渲染的，这一块可以再深究一下」。当前项目只能出码下载，缺少真正的发布-访问流程。

**约束条件**：
- 项目部署在 GitHub Pages（纯静态托管，无后端）
- 需要兼容未来迁移到 Vercel/服务器的场景

**技术决策**：
- 存储方案：URL Hash 编码 + localStorage 缓存（无后端依赖）
- 事件编排：提取到 `@lowcode/shared` 新包（规范复用）
- 渲染方式：先 CSR，SSR 作为 P3 优化项

**schemaCodec.ts 核心逻辑**：
```typescript
import LZString from 'lz-string';

export function encodeSchema(schema: PublishRequest): string {
  const json = JSON.stringify(schema);
  const compressed = LZString.compressToEncodedURIComponent(json);
  return compressed;
}

export function decodeSchema(encoded: string): PublishRequest | null {
  try {
    const json = LZString.decompressFromEncodedURIComponent(encoded);
    return json ? JSON.parse(json) : null;
  } catch {
    return null;
  }
}
```

**urlHashSchemaService.ts 核心逻辑**：
```typescript
export class UrlHashSchemaService implements ISchemaService {
  private readonly STORAGE_KEY = 'lowcode-published-pages';
  private readonly RUNTIME_BASE = '/runtime/#/page';

  async publish(data: PublishRequest): Promise<PublishResponse> {
    const pageId = nanoid(8);
    const encoded = encodeSchema({ ...data, id: pageId });
    const pageUrl = `${this.RUNTIME_BASE}?data=${encoded}`;
    
    // 同时存入 localStorage 作为历史记录
    this.saveToHistory({ id: pageId, title: data.title, publishedAt: new Date().toISOString() });
    
    return { success: true, pageId, pageUrl };
  }

  async getPage(pageId: string): Promise<PublishedPage | null> {
    // 从 URL 参数解析，或从 localStorage 获取
  }
}
```

**App.tsx 路由配置**：
```tsx
import { HashRouter, Routes, Route } from 'react-router-dom';

export default function App() {
  return (
    <HashRouter>
      <Routes>
        <Route path="/page" element={<PageRenderer />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </HashRouter>
  );
}
```

**PageRenderer.tsx 核心逻辑**：
```tsx
export default function PageRenderer() {
  const [searchParams] = useSearchParams();
  const { components, rootId, loading, error } = useRuntimeStore();
  const { handleEvent, handleCompRef } = useEventOrchestrator({ 
    components, 
    componentConfig: componentConfigMap 
  });

  useEffect(() => {
    const encoded = searchParams.get('data');
    if (encoded) {
      const schema = decodeSchema(encoded);
      if (schema) {
        useRuntimeStore.getState().setPage(schema);
      } else {
        useRuntimeStore.getState().setError('页面数据解析失败');
      }
    }
  }, [searchParams]);

  if (loading) return <PageSkeleton />;
  if (error) return <NotFound message={error} />;

  return (
    <SchemaRenderer
      components={components}
      rootId={rootId}
      componentMap={componentConfigMap}
      designMode="live"
      onEvent={handleEvent}
      onCompRef={handleCompRef}
    />
  );
}
```

## 未来迁移到 Vercel/服务器

当条件允许时，迁移步骤：

1. **新增 ApiSchemaService**
   ```typescript
   class ApiSchemaService implements ISchemaService {
     async publish(data) {
       return fetch('/api/pages', { method: 'POST', body: JSON.stringify(data) });
     }
     async getPage(id) {
       return fetch(`/api/pages/${id}`).then(r => r.json());
     }
   }
   ```

2. **替换服务实例**
   ```typescript
   // 从
   const schemaService = new UrlHashSchemaService();
   // 改为
   const schemaService = new ApiSchemaService();
   ```

3. **添加后端 API**（Next.js API Routes 或 Express）

4. **可选：添加 SSR**

**迁移成本**：约 1-2 天，核心渲染逻辑零改动。

## 面试话术

> "我实现了运行时渲染服务，从出码模式改成了 Schema 驱动的动态渲染。
>
> 考虑到项目部署在 GitHub Pages，我用 URL Hash 编码 Schema 的方案实现了无后端的发布流程。Schema 经过 LZ-String 压缩后 Base64 编码放在 URL 中，同时存入 localStorage 作为历史记录。
>
> 关键设计是抽象了 ISchemaService 接口，当前用 UrlHashSchemaService 实现，未来迁移到 Vercel 只需要实现 ApiSchemaService 替换即可，运行时渲染逻辑完全不变。
>
> 这样做的好处是：
> 1. 发布即生效，无需构建部署
> 2. 兼容静态托管，无后端依赖
> 3. 架构可扩展，迁移成本低"
