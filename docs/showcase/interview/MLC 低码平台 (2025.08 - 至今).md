## MLC 低码平台 (2025.08 - 至今)

**项目描述**：

一款 **Schema 驱动的跨框架低代码平台**，支持可视化拖拽与 React / Vue 双端渲染。采用 Monorepo 架构，包含设计器（Designer）、渲染器（Renderer）及物料库（Material Lib）等核心模块。

**技术栈**：

React, Vue, Zustand, Yjs, Vite, Tailwind CSS, Nx

### 技术实现

#### 1. 跨框架渲染引擎

- **架构设计**：采用 `Schema` -> `Parser` -> `Renderer` 三层抽象，将核心逻辑（状态管理、组件树处理）抽离为**框架无关层**。
- **代码复用**：React 和 Vue 仅作为视图层的映射实现，核心逻辑复用率达 **70%** 以上。

#### 2. 响应式数据绑定系统

- **上下文管理**：实现了 5 层表达式上下文：`$global`、`$page`、`$data`、`$props`、`$system`。
- **绑定模式**：支持**变量、表达式、数据源**三种绑定模式。
- **性能优化**：基于 `new Function` 沙箱求值结合 **AST 依赖提取**实现自动更新，表达式执行耗时小于 $1\text{ms}$。

#### 3. CRDT 实时协作

- **协同机制**：基于 **Yjs** 实现多人同时编辑，将 Schema 操作转换为 CRDT 原子操作，原生支持离线编辑与自动冲突合并。
- **通信保障**：采用 WebSocket + 心跳保活机制，支持断线后的增量同步，协作延迟控制在 $100\text{ms}$ 以内。

#### 4. 微前端预览与出码系统

- **沙箱通信**：通过 `iframe` + `postMessage` 实现双向通信，设计了 6 种统一的消息类型协议；引入消息队列与 Ready 握手机制确保消息零丢失。
- **传输优化**：采用 **Schema Patch 增量同步**技术，减少了 **85%** 的数据传输体积。
- **自动化出码**：实现 `Schema` -> `AST` -> `Code` 的转换链路，利用模板引擎与 Prettier 格式化，支持一键导出标准的 React/Vue 工程代码。

## Branch 4: `refactor/collab-crdt`

### 目标

将协同编辑从**朴素 JSON Patch 全量同步**升级为基于 **Yjs (CRDT)** 的无冲突实时协同。

### 技术选型分析

| 方案                           | 优点                                                         | 缺点                                                   | 结论       |
| :----------------------------- | :----------------------------------------------------------- | :----------------------------------------------------- | :--------- |
| **OT (Operational Transform)** | 成熟（Google Docs 使用）                                     | 需要中心化服务器做变换、实现极其复杂、难以扩展到树结构 | ❌ 不推荐   |
| **你现有的 Rebase 方案**       | 简单、已实现                                                 | 容易丢操作、冲突时依赖全量 Sync、无法 offline          | ❌ 需升级   |
| **Automerge**                  | CRDT、支持离线、JSON 友好                                    | 库体积大(~200KB)、Rust WASM 依赖可能有兼容问题         | ⚠️ 可选     |
| **Yjs**                        | CRDT、体积小(~15KB)、生态最好（有 `y-websocket`、`y-indexeddb`）、树结构原生支持(`Y.Map`/`Y.Array`) | 学习曲线                                               | ✅ **推荐** |

**推荐使用 Yjs**。理由：

1. 你的 Schema 本质是

    

   ```
   Record<number, Component>
   ```

   （一个 Map），Yjs 的

    

   ```
   Y.Map
   ```

    

   天然对应。

2. ```
   y-websocket
   ```

    

   直接替代你的手写 WebSocket 逻辑，省去大量代码。

3. ```
   y-indexeddb
   ```

    

   可以无缝实现离线编辑 + 在线自动合并。

4. Yjs 在前端低代码/设计工具领域有大量实战案例（Figma 思路类似）。

      callback(yjsToComponents(this.doc));

    });

  }



  /** 感知信息（光标、选中） */

  get awareness() { return this.provider.awareness; }

}
```

**Step 4.7：处理冲突的核心优势**

用 Yjs 后，你之前 PRD 中提到的 **C4. 状态纠正** 问题自动消失：

| 冲突场景                                                 | 当前方案                     | Yjs 方案                                    |
| :------------------------------------------------------- | :--------------------------- | :------------------------------------------ |
| A 改 Button.text = "确定"，B 同时改 Button.text = "取消" | 后到的覆盖先到的，可能丢数据 | CRDT 自动合并，Last Writer Wins (可预测)    |
| A 删除组件 3，B 同时在组件 3 上修改 props                | 全量 Sync 回滚 B 的操作      | B 的修改自动丢弃（target 已被删除），无报错 |
| A 移动组件到容器 X，B 同时移动同一组件到容器 Y           | 不可预测                     | CRDT 保证最终一致，两端都会收敛到同一结果   |
| 网络断开 30 秒后重连                                     | 触发全量 Sync                | Yjs 自动差量同步，离线期间的操作无缝合并    |
