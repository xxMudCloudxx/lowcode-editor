# 🚀 低代码项目简历亮点 (STAR 法则提炼)

以下内容基于“低代码平台”的十大核心架构模块，使用 **STAR法则（Situation情境、Task任务、Action行动、Result结果）** 进行提炼。你可以直接挑选 3-4 个你最有把握的模块，稍微精简后写进简历的“项目核心成就/亮点”中。

### 1. 架构演进：从单体（Monolith）到 Monorepo 的重构治理
*   **[S] 情境**：项目初期采用单体架构，协议层、编辑器状态与底层选型深度耦合，导致开发体验极度混乱，不仅编译速度慢且引入第三方图表（AntV等）时极易发生依赖冲突与逻辑交叉。
*   **[T] 任务**：负责主导底层的架构重构，解耦“编辑器运行环境”与“运行时数据结构”，打造一个插件化、可无限拓展基础组件的高拓展性底座。
*   **[A] 行动**：使用 `pnpm workspace` 引入 Monorepo 治理方案，强行切分代码物理边界：
    1. 剥离了零依赖的 `@lowcode/schema`（定义 ComponentProtocol 与 JSON AST）。
    2. 基于协议壳（forwardRef高阶代理），将 Antd 等 UI 库无缝包装封装成 `@lowcode/materials` 独立发包。
    3. 抽离了剥除一切编辑器状态的纯净函数机 `@lowcode/renderer`。
*   **[R] 结果**：实现了各包的按需编译与单向依赖流转，编辑器整体冷启动构建速度提升 50% 以上；奠定了可以“免入侵主仓库即可拔插第三方图表物料包”的泛生态能力。

### 2. UI 基建：基于双令牌（Dual-Token）的 `O(1)` 主题定制引擎
*   **[S] 情境**：传统低代码产品在实现“生成产物主题定制”时，往往采用暴力下发冗长内联 CSS 或强行覆盖类名的做法，导致渲染出码的产物 CSS 体积臃肿，且定制颗粒度极难控制。
*   **[T] 任务**：设计一套高性能、低侵入、能够兼顾全局品牌色与局部组件“基因突变”的动态换肤方案。
*   **[A] 行动**：深度结合 Ant Design V5 的 CSS-in-JS 与 Token 化机制设计主题配置流：
    1. 在全局设置面板基于 `Seed Token`（主色、圆角基数）由算法自动演化全局的 `Map Token` 实现全局一键换肤。
    2. 在右侧组件的属性配置面板暴露 `Component Token`（特定组件的具体值），允许用户对特定的组件实例做样式覆写（`override`）突破全局约束。
*   **[R] 结果**：彻底摒弃了繁重的 class 覆盖，实现了 `O(1)` 复杂度的全局主题应用响应，极大地提升了出码产物工程的纯净度。

### 3. 数据流管理：依托 Zustand的极简时间旅行（Undo/Redo）机制
*   **[S] 情境**：低代码画板在编排时有着极高频次的数据更新（拖拉拽、微调属性），如果采用全量 DOM 记录或暴力的 JSON 全局深拷贝会造成极其严重的浏览器内存泄漏和卡顿。
*   **[T] 任务**：在保证性能的前提下，为用户提供极其丝滑且无错漏的“撤销/重做（History Stack）”功能。
*   **[A] 行动**：
    1. 摒弃 Redux 的繁重流转，以 Zustand 作为全局数据控制大脑。
    2. 引入 `Immer.js`。将所有的更新行为抽象为针对中心化 `JSON Schema (AST)` 的微突变（`mutations`）。
    3. 设计历史记录中间件，通过追踪 `Immer` 产生的 patch 反转（`inverse patch`），只在内存栈中记录极小字节的增量指令变更状态。
*   **[R] 结果**：以极低的堆内存消耗实现了理论无限深度的操作撤回。不仅保障了画板高频状态更新不卡顿，更规范了系统底层从“命令式数据修改”到“数据指令追溯”的演进。

### 4. 沙盒机制：Iframe 环境与编辑器的 PostMessage 安全握手
*   **[S] 情境**：用户在配置区写入的全局副作用 CSS 或者不可控的脚本（比如定时器、错误死循环 JS）非常容易导致当前编辑器的宿主进程卡死或被样式污染。
*   **[T] 任务**：搭建编辑态视图与运行态视图的硬性物理隔离墙。
*   **[A] 行动**：
    1. 引入 Iframe 沙盒机制。重写了 [Preview](file:///d:/Desktop/proj/A.Front-End/Program/lowcode-editor/packages/editor/src/editor/components/Preview/index.tsx#28-154) 组件与 `@lowcode/renderer`，将其从 DOM 同级组件变成了嵌套 Iframe。
    2. 收敛主应用状态：不再允许 Iframe 读取 Zustand，改为通过 `window.postMessage` 仅桥接同步标准化 JSON Schema 数据与鼠标事件交互（Hover 坐标透传）。
    3. 加入 `sandboxExecutor` 函数生成虚拟执行上下文防御跨域风险脚本。
*   **[R] 结果**：实现了类似大厂云产品的防崩溃级别视图隔离保障。任何由于组件内部死循环或全局 `!important` 造成的故障与样式穿透都被 100% 钳制在了 Iframe 内部。

### 5. 拖拽引擎：React-DND 与画布几何碰撞计算
*   **[S] 情境**：将物料组件拖入画布区时，存在极其复杂的嵌套容器规则判定及其导致的闪烁光标渲染异常。
*   **[T] 任务**：实现一套流畅的跨边界拖拽系统，能平滑实现“自由拖拽”、“高亮占位符提示”、“合法容器判断”功能。
*   **[A] 行动**：基于 `React-DND` 和 `@dnd-kit` 构建拖拉拽上下文。在编辑层的视图之上独立绘制了一个高频刷新、脱离正常文档流的 `Absolute Layer` 用于追踪光标实时映射出 `SelectedMask` 和 `HoverMask`，同时配合 AST 解析预先拦截非法嵌套（例如表单组件内禁止拖放全局容器）。
*   **[R] 结果**：大幅优化了画布中涉及 DOM 重排的拖拽行为体验边界判定；保障了拖拽中的 60FPS 丝滑体验。

### 6. 出码引擎：可插拔式 AST 代码生成流水线设计
*   **[S] 情境**：单纯保存一组 JSON 数据往往只能算是“页面配置器”。要真正配得上“低代码/ProCode”的名号，需要能生成可以直接用来上库并接手的 React 前端工程代码。
*   **[T] 任务**：基于 JSON Schema，实现一套支持生成包含依赖树、模板脚手架并且代码格式规范的开源级 React 项目代码。
*   **[A] 行动**：
    1. 将出码系统从单体剥离为 `@lowcode/code-generator` 包。
    2. 设计“多遍扫描”架构（第一遍收集依赖和状态，第二遍由 AST 工具将配置化 JSON 编译转化为 React JSX Node，第三遍处理后置格式化如使用 `Prettier`）。
    3. 设计了基于插件注册机制的出码体系。
*   **[R] 结果**：成功支持了一键打包为 `React+Vite` 工程，产出代码整洁清晰，大幅提升了平台的交付价值能力，也为以后接入 Vue 或小程序的编译插件留出了架构级的插槽。
