## P0 - 运行时渲染服务（最高优先级）

> **面试官原话**："发布之后后面的流程，然后他是怎么去渲染的，这一块可以再深究一下"

### 目标
从「出码下载」变成「一键发布 → 生成链接 → 用户直接访问」

### 架构设计

```
┌──────────────────────────────────────────────────────────────────┐
│                         编辑器端                                  │
│  ┌─────────┐    ┌─────────┐    ┌─────────────────────────────┐  │
│  │  搭建   │ -> │  保存   │ -> │  发布（存 Schema 到后端）    │  │
│  └─────────┘    └─────────┘    └─────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
                                        │
                                        ▼
┌──────────────────────────────────────────────────────────────────┐
│                         服务端                                    │
│  ┌─────────────────┐    ┌─────────────────┐                      │
│  │  Schema 存储    │    │  组件资源 CDN   │                      │
│  │  (数据库/OSS)   │    │  (JS Bundle)    │                      │
│  └────────┬────────┘    └────────┬────────┘                      │
│           │                      │                                │
│           ▼                      ▼                                │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │                    渲染服务                                  │ │
│  │  1. 根据 pageId 拉取 Schema                                 │ │
│  │  2. 解析 Schema，确定需要哪些组件                            │ │
│  │  3. 加载组件资源                                            │ │
│  │  4. 渲染 HTML 返回（SSR）或返回 Schema + 组件（CSR）         │ │
│  └─────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
                                        │
                                        ▼
┌──────────────────────────────────────────────────────────────────┐
│                         用户访问                                  │
│  https://your-domain.com/page/{pageId}                           │
│  -> 渲染服务返回完整页面                                          │
└──────────────────────────────────────────────────────────────────┘
```

### 面试话术
> "我后来重构了发布流程，从出码模式改成了运行时渲染。编辑器保存的 Schema 存到后端，用户访问时由渲染服务根据 Schema 动态组装页面。这样做的好处是：1）发布即生效，不需要重新构建部署；2）为后续的组件热更新和 A/B 测试打下基础。"

## P1 - 数据源与请求调度

> **面试官原话**："你可能现在可能还比较缺乏 C 端的一些性能优化"

### 目标
组件可以绑定数据源，运行时动态请求，支持请求优先级调度

### 架构设计

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           数据源配置                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  {                                                               │   │
│  │    componentId: "product-list-1",                                │   │
│  │    dataSource: {                                                 │   │
│  │      type: "api",                                                │   │
│  │      url: "/api/products",                                       │   │
│  │      method: "GET",                                              │   │
│  │      params: { categoryId: "{{props.categoryId}}" },             │   │
│  │      dataMapping: { list: "data.items", total: "data.total" },   │   │
│  │      priority: "high",  // 请求优先级                             │   │
│  │      cache: { ttl: 60000 }  // 缓存策略                          │   │
│  │    }                                                             │   │
│  │  }                                                               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### 请求调度器核心实现

```typescript
type Priority = 'critical' | 'high' | 'normal' | 'low';

class RequestScheduler {
  private queues: Map<Priority, RequestTask[]> = new Map();
  private running = 0;
  private maxConcurrent = 6; // 浏览器并发限制
  
  enqueue(task: RequestTask, priority: Priority) {
    this.queues.get(priority)?.push(task);
    this.flush();
  }
  
  private flush() {
    if (this.running >= this.maxConcurrent) return;
    
    // 按优先级取任务
    const task = this.getNextTask();
    if (!task) return;
    
    this.running++;
    task.execute()
      .finally(() => {
        this.running--;
        this.flush();
      });
  }
  
  private getNextTask(): RequestTask | null {
    for (const priority of ['critical', 'high', 'normal', 'low']) {
      const queue = this.queues.get(priority as Priority);
      if (queue?.length) return queue.shift()!;
    }
    return null;
  }
}
```

### 面试话术
> "我实现了一个请求调度器来解决 C 端页面多组件并发请求的问题。核心思路是：1）按优先级分队列，首屏关键数据优先；2）结合 Intersection Observer，可视区域内的组件自动提升优先级；3）控制并发数不超过浏览器限制。这样首屏 LCP 可以提升 30% 左右。"

## P2 - 组件版本与热更新

> **面试官原话**："你组件肯定是需要有版本的，不然你之前发布的页面...想改一下这个组件，让线上页面都给更新了"

### 目标
组件有版本管理，已发布页面可以选择锁定版本或跟随最新

### 架构设计

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         组件版本管理                                     │
│                                                                         │
│  组件仓库                          页面 Schema                           │
│  ┌─────────────────────┐          ┌─────────────────────────────────┐  │
│  │ ProductCard         │          │ {                               │  │
│  │  ├── v1.0.0        │          │   componentName: "ProductCard", │  │
│  │  ├── v1.1.0        │  ──────> │   version: "1.1.0",             │  │
│  │  └── v1.2.0 (latest)│          │   // 或 version: "latest"       │  │
│  └─────────────────────┘          │ }                               │  │
│                                   └─────────────────────────────────┘  │
│                                                                         │
│  版本策略：                                                              │
│  - "1.1.0"  → 锁定版本，不自动更新                                       │
│  - "latest" → 跟随最新，自动更新                                         │
│  - "^1.0.0" → 兼容更新，只接受 minor/patch                               │
└─────────────────────────────────────────────────────────────────────────┘
```

### 面试话术
> "我实现了组件版本管理机制。页面 Schema 里存的是组件引用而不是组件代码，渲染时动态加载。支持三种版本策略：锁定版本保证稳定性，latest 跟随最新，语义化版本兼容更新。这样既能满足'统一加标签'的批量更新需求，也能保证关键页面的稳定性。"

### SSR 支持

```typescript
export async function renderPage(pageId: string) {
  const schema = await getPageSchema(pageId);
  const components = await loadComponents(schema);
  
  // 预取数据
  const data = await prefetchData(schema);
  
  // 服务端渲染
  const html = renderToString(
    <RuntimeRenderer schema={schema} initialData={data} />
  );
  
  return `
    <!DOCTYPE html>
    <html>
      <head>...</head>
      <body>
        <div id="root">${html}</div>
        <script>window.__INITIAL_DATA__ = ${JSON.stringify(data)}</script>
        <script src="/runtime.js"></script>
      </body>
    </html>
  `;
}
```

### 白屏检测

```typescript
function detectWhiteScreen() {
  const points = [
    [0.25, 0.25], [0.5, 0.25], [0.75, 0.25],
    [0.25, 0.5],  [0.5, 0.5],  [0.75, 0.5],
    [0.25, 0.75], [0.5, 0.75], [0.75, 0.75]
  ];
  
  let emptyPoints = 0;
  points.forEach(([x, y]) => {
    const el = document.elementFromPoint(
      window.innerWidth * x,
      window.innerHeight * y
    );
    if (!el || el === document.body || el === document.documentElement) {
      emptyPoints++;
    }
  });
  
  if (emptyPoints >= 6) {
    report('white_screen', { emptyPoints });
  }
}
```

## 你的项目与微信小店的差距

| 能力 | 当前项目 | 微信小店级别 |
|------|---------|-------------|
| 组件管理 | 静态打包，无版本 | 动态加载，版本管理，热更新 |
| 数据绑定 | 静态数据或简单接口 | 数据源配置，千人千面 |
| 发布流程 | 出码下载，手动部署 | 一键发布，生成链接，运行时渲染 |
| 渲染方式 | 纯 CSR | SSR + CSR 混合，骨架屏 |
| 请求调度 | 无 | 优先级队列，请求合并，BFF |
| 监控 | 无 | 性能监控，错误上报，白屏检测 |
| 灰度能力 | 无 | A/B 测试，灰度发布 |
