这个项目到底在解决什么问题

先把项目定位讲准：它不是单纯的拖拽编辑器，而是一套以 Schema 为单一数据源的低代码平台。

一句话先定性

更准确的说法是：这是一个基于 Schema 驱动的低代码平台。用户通过拖拽和配置搭建页面，系统再把这些操作沉淀成统一的组件树和后续代码产物。

出

PLAIN ENGLISH

整个应用先搭了一个全屏编辑器外壳。

上面是一条工具栏，下面根据模式切成编辑态或预览态。

编辑态下主区域被拆成三栏，分别对应物料、画布和设置。

预览态则直接显示最终页面，不再展示工作台结构。

完整动作其实是“拖、配、看、出”

1
拖一个组件进画布

用户做拖拽动作，系统开始收集物料信息。

2
在右侧改属性、样式、事件

这些修改会回到组件树，而不是直接写死在 DOM 上。

3
切到预览态

同一份数据会被重新解释成最终页面。

4
导出源码

当前 Schema 会被送入 Worker 和出码流水线，生成真实项目。
