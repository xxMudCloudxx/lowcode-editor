拖进去的组件为什么能出现在画布上

关键不是“往 DOM 里塞一个节点”，而是“先改数据，再由渲染器递归解释”。

先追踪完整链路

在低代码系统里，拖拽只是入口。真正重要的是后面的四步：把物料元数据带进上下文、校验容器能不能接收、更新组件树、让渲染器根据新状态重画。

第一步：拖拽时先带上物料档案

物料卡片并不是只说“我被拖起来了”，它还会把组件名、默认属性和描述发给宿主。这样 drop 成功后，主编辑器能立刻创建出一个带默认配置的新节点。

CODE 
  const handleDragStart = (e: React.DragEvent) => {
    e.dataTransfer.setData("text/plain", `lowcode-component:${name}`);
    e.dataTransfer.effectAllowed = "copy";

    const config = componentConfig[name];
    if (config) {
      simulatorHost.sendDragStartMetadata({
        componentName: name,
        defaultProps: config.defaultProps ?? {},
        desc: config.desc,
      });
    }
  };
PLAIN ENGLISH

拖拽开始时，先给浏览器原生拖拽系统放一个标识。

然后去物料配置中心找到这个组件的默认信息。

如果找到了，就把组件名、默认属性和描述发给宿主通信层。

所以后面的 drop 不是凭空造节点，而是带着一份完整的物料档案在处理。

第二步：先写入规范化组件树

这个仓库没有把页面存成一棵深层嵌套对象，而是把实例都放进按 id 索引的 Map。这样增删改查更稳定，也更适合做撤销重做和局部重渲染。

CODE 
  addComponent: (component, parentId) => {
    set((state) => {
      const parent = state.components[parentId];
      if (!parent) return;

      const newComponent: Component = structuredClone(component);
      if (!newComponent.id) {
        newComponent.id = generateUniqueId();
      }
      newComponent.parentId = parentId;
      newComponent.children = [];
      state.components[newComponent.id] = newComponent;
      if (!parent.children) parent.children = [];
      parent.children.push(newComponent.id);
    });
  },
PLAIN ENGLISH

新增组件时，先找到它要挂到哪个父节点下面。

把模板克隆一份，并补上新的实例 id。

再把 parentId、children 等结构信息补齐，写进 components Map。

最后只要把这个新 id 挂到父节点 children 列表里，树结构就成立了。
