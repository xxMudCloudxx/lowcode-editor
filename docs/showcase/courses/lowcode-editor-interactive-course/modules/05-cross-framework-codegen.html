跨框架出码流水线怎么跑起来

这是你简历里最值钱的主线：Schema 先转成通用 IR，再通过 Solution 切到 React 或 Vue 出码。

先看整条出码流水线

更高级的讲法不是“能导出代码”，而是“先把页面语义标准化，再通过不同 Solution 接入不同框架”。这就是为什么 React 和 Vue 能共用同一套主流程。

注册中心会先装入物料包里的描述符和自定义逻辑。

后面的具体框架差异，都建立在已经统一好的 IR 之上。

IR

先标准化，再分流

IR 负责统一页面语义，避免主流程直接绑定某个框架。

Reg

物料注册中心

组件依赖、标签映射、属性过滤和自定义逻辑都通过注册接入。

Sol

Solution 抽象

React 和 Vue 只是不同方案，而不是两套独立流程。

PLAIN ENGLISH

每次点导出，先给这次任务一个新的请求编号。

如果还有旧任务没结束，就先重启 Worker，把旧任务当作取消处理。

这样连续切换方案时，永远只保留最后一次请求的结果。

同时再挂一个超时器，防止 Worker 卡死后一直占着这次任务不返回。
